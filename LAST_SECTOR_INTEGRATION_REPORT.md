## Найдено и исправлено мной в этой сессии (не поймано их аудитом)

### 1–3. Бот-функция `botAction()` в `src/index.js` — тройной баг в одном месте

Их собственные 13 (не 17, как заявлено — мелкая неточность в их доке) тестов **никогда не вызывали реальные `lastSectorPack.bots.random`/`.aggressive`** — их же fuzz-тест переизобретает выбор действия внутри себя. Поэтому баги в реальной бот-логике были невидимы их набору целиком.

- `neighbors(unit.coord.q, unit.coord.r)` — `coord` строка `"q,r"`, не объект → `undefined`/`NaN` → бот никогда не находил валидный ход.
- Даже с исправленным парсингом, `neighbors()` возвращал объекты `{q,r}`, а протокол MOVE требует строку — второй независимый способ провалить каждый ход.
- Самый серьёзный: `offsetNeighbors` (настоящий валидатор в `game.js`) использует **разные смещения для чётных/нечётных строк** hex-сетки, бот — фиксированный набор, совпадающий только с чётным случаем → систематический `OUT_OF_RANGE` на нечётных строках.

**Фикс:** убрал дублирование hex-геометрии целиком — экспортировал `offsetNeighbors` из `game.js`, бот использует ровно ту же функцию, что и настоящий валидатор.

### 4. `FORCED_DIRECTION`

Бот не проверял тайлы с принудительным направлением движения. Добавил фильтрацию кандидатов по `currentTile.forceTo`.

### 5. Nebula блокирует ATTACK

Агрессивный бот не проверял, что сам стоит на `resolved`-небуле (где атака запрещена правилом игры, как и в `validateAction`). Добавил проверку.

**Прогресс по стресс-тесту:** после фикса 1-3 — с systematic failures до единичных редких отказов; после фикса 4-5 — **0 отказов** на 21506+10727 шагах (два независимых прогона, включая чистую копию).

### Побочная находка: их же тест содержал ошибку в сетапе

`adversarial.test.js`'s "aggressive bot can detect adjacent enemy ships" ставил `b.home = neighbor` — то есть цель оказывалась «дома», где её **нельзя** атаковать по настоящему правилу игры (`target.coord === target.home` → `INVALID_TARGET`). Мой фикс (исключение at-home целей из поиска бота) сначала сломал этот тест — но правильно, потому что тест сам был некорректен. Исправил тест (не трогая `home`), добавил ассерт, что предложенное ботом действие реально проходит `validateAction`, а не просто выглядит правильно в изоляции.

## Самая важная находка: заявленный `role:tv`-канал не работал вообще

Аудит утверждает: *«The Last Sector presentation stream is now explicitly addressed to role:tv»*. Проверка показала: **нигде в паке буквально не встречается `role:tv`**. `emitPresentation()` в `game.js` по-прежнему скоупит события только на актора.

Их собственный тест на это (`presentation events are explicitly TV-scoped...`) молча проходил, потому что использовал `END_TURN` — действие, которое **не генерирует ни одного presentation-события вообще**. `[].every(predicate)` тривиально `true` для пустого массива — тест не проверял ничего.

**Фикс на трёх уровнях:**
1. `emitPresentation()` теперь добавляет `'role:tv'` к audience (не заменяя, а дополняя существующий scoping на актора — приватность игрок-к-игроку не тронута).
2. Переписал их тест на реальный MOVE (действительно порождает `ROUTE_HIGHLIGHT`/`SHIP_MOVE_ANIMATION`), добавил проверку и на позитив (`role:tv` присутствует), и на негатив (другой игрок не получает).
3. **Обнаружил более глубокий пробел в своей же прошлой работе**: `createTokenAuth` вообще не позволял выпустить токен с ролью `'tv'` — весь механизм `role:X`-таргетинга событий (который я строил несколько сессий назад) был технически рабочим, но недостижимым end-to-end, потому что auth-слой ограничивал роли только `['player','spectator']`. Добавил `allowedRoles` (явный opt-in при создании `createTokenAuth`, backward compatible — дефолт не изменился).

**Сквозной тест:** настоящий `ServerHost` + настоящий `createProtocolServer` + настоящий `createWsServer`/`createWsClient` — реальный TV-клиент по реальному WebSocket получает presentation-событие, реальный игрок B — нет. Это первый тест во всём паке, который вообще гоняет Last Sector через полный сетевой стек, а не только через прямые вызовы `applyActionInPlace`/`validateAction`.
